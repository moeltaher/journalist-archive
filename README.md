# أرشيف الصحفي — Journalist Archive

أداة مجانية تعمل من الهاتف ومن المتصفح لمساعدة الصحفيين والكُتّاب في حفظ نسخ من أعمالهم المنشورة. يبدأ الاستخدام برابط واحد، سواء لرابط **مقال منفرد** أو **صفحة كاتب تحتوي على عدة مقالات**.

بعد تحليل الرابط تظهر المقالات المكتشفة في قائمة قابلة للتحديد، مع خيارين منفصلين:

- **تنزيل Word:** استخراج النصوص المتاحة للمقالات المحددة وتجميعها في ملف `.docx` واحد باتجاه كتابة عربي RTL، بما يشمل العناوين والمعلومات الوصفية والرابط الأصلي. يتم إنشاء الملف في المتصفح ويُنزَّل مباشرة على جهاز المستخدم.
- **الأرشفة في Wayback Machine:** إرسال روابط المقالات المحددة إلى واجهة Save Page Now 2 الرسمية، ثم متابعة حالة حفظ كل رابط. بعد اكتمال المتابعة يفتح التطبيق صفحة نتائج مستقلة تعرض روابط النسخ المؤرشفة المؤكدة، وتفصلها عن حالات الفشل وعدم التأكيد.

## النشر من الهاتف باستخدام Cloudflare Workers

1. أنشئ حسابًا مجانيًا في Cloudflare ومستودع GitHub للمشروع.
2. في لوحة **Workers & Pages > Create application > Connect GitHub** اختر المستودع.
3. اضبط **Project name** على `journalist-archive`، واترك **Build command** فارغًا. استخدم **Deploy command**: `npx wrangler deploy`.
4. اضغط **Deploy**. يتيح Cloudflare نطاقًا من نوع `*.workers.dev`، ويمكن تغيير النطاق لاحقًا. عند تحديث الفرع `main` على GitHub ينشر Cloudflare التحديثات تلقائيًا إذا كان GitHub Builds متصلًا ومفعّلًا.
5. جرّب إدخال رابط مقال، ثم الضغط على «تنزيل ملف Word».

لا تحتاج الواجهة إلى Vite أو حزم JavaScript خارجية. يستخدم المشروع `HTMLRewriter` المدمج مع Cloudflare Workers لاستخراج بيانات الصفحات، ويُنشئ Word محليًا بتنسيق OOXML.

### تفعيل الأرشفة الآلية — خطوة إعداد مستقلة

**الأرشفة الآلية تحتاج مفاتيح Internet Archive.** إنشاء الموقع وحده لا يكفي.

1. سجّل الدخول إلى حسابك الشخصي في [Internet Archive](https://archive.org/).
2. افتح صفحة [S3 Keys](https://archive.org/account/s3.php) واحصل على مفتاح الوصول والمفتاح السري وفق شروط Internet Archive.
3. من لوحة Cloudflare افتح **Workers & Pages > journalist-archive > Settings > Variables and Secrets**.
4. أضف القيمتين التاليتين بصفتهما **Secret** (وليس plain text variable):
   - `IA_ACCESS_KEY` = مفتاح الوصول.
   - `IA_SECRET_KEY` = المفتاح السري.
5. احفظ الإعدادات وطبّقها على النشر، ثم أعد تحميل التطبيق. سيتفعّل زر الأرشفة.

**لا تضع المفاتيح في GitHub أو في ملفات المشروع ولا ترسلها داخل محادثة.** قبل إعداد المفاتيح، يوفر التطبيق رابطًا للحفظ اليدوي في Wayback عند تحديد مقال واحد.

## تقرير روابط الأرشفة

بعد الضغط على «أرشفة وعرض الروابط»، يُعالج التطبيق المقالات المحددة بالتتابع ويتحقق من حالة كل عملية. **بعد انتهاء متابعة الطلبات** ينتقل تلقائيًا إلى `/archive-results.html`، ويعرض:

- عنوان كل مقال ورابطه الأصلي، ورابط نسخة Wayback المؤكدة مع زر «فتح النسخة» و«نسخ الرابط».
- عدادًا للمقالات المؤرشفة والطلبات الفاشلة وغير المؤكدة، مع توضيح ما حدث لكل مقال.
- زرين لنسخ الروابط الناجحة مجتمعة أو تنزيلها كملف TXT عربي.

يُحفظ **آخر تقرير فقط** في التخزين المحلي لنفس المتصفح ليمكن الرجوع إليه من الصفحة الرئيسية؛ ليس رابط التقرير تقريرًا عامًا يمكن مشاركته على أجهزة أخرى. إن أغلق المستخدم الصفحة أثناء الأرشفة فقد لا يكتمل تشغيل الطلبات والمتابعة، وحالة «قيد الانتظار» لا تعني نجاح الأرشفة. لا تُعرض نسخة Wayback مؤكدة إلا حين ترجع خدمة Internet Archive رابطًا قابلًا للبناء من نتيجة نجاح ذات طابع زمني ورابط أصلي صالحين.

## حدود النسخة الأولى

- تكتشف الأداة المقالات من صفحات HTML العامة؛ بعض المواقع تتطلب JavaScript أو تمنع الروبوتات، ما قد يجعل القوائم أو النصوص غير متاحة للاستخراج.
- قد لا يعثر الاكتشاف التلقائي على كل المقالات أو يرشح روابط غير صحيحة. يستطيع المستخدم تغيير نوع الصفحة يدويًا ومراجعة كل مقال قبل البدء.
- تدعم قوائم الكُتّاب روابط الصفحات المرقمة و`rel=next` وروابط «Load More / تحميل المزيد» التي يمكن استخراج عنوانها من HTML، وبعض الأزرار ذات خصائص `data-url` وقوائم `JSON-LD ItemList`، دون تخصيص الكود لموقع بعينه.
- يعرض التطبيق حتى **45 رابطًا في الدفعة**، مع مؤشر لاستكمال صفحات الكاتب لاحقًا وتجنب تحديد المقالات المؤرشفة سابقًا تلقائيًا؛ وقد يفحص حتى **4 صفحات** في عملية اكتشاف واحدة.
- لا يدير Cloudflare Worker متصفحًا آليًا في هذا الإصدار. إن كانت القائمة تُنشأ فقط عند التمرير، أو عبر JavaScript / AJAX / GraphQL دون رابط HTML واضح، فقد لا يكتشف الصفحات التالية. دعم هذه الحالة يحتاج طبقة تصفح ديناميكي مستقلة مع تحديد حصص الاستهلاك والقيود الأمنية.
- يضم Word النصوص والعناوين والبيانات الوصفية والروابط، ولا يضمن نقل الصور أو الجداول أو التنسيق الأصلي حرفيًا.
- لا تُحفَظ المقالات في قاعدة بيانات؛ تُعالَج مؤقتًا في Worker ثم تُنقَل إلى المتصفح. لا يتطلب التطبيق إنشاء حساب مستخدم.
- تخضع عمليات الأرشفة إلى حدود Internet Archive؛ والأرشفة الناجحة لا تُفترَض إلا بعد التحقق من حالة مهمة Save Page Now.
- الأرشفة الجماعية تدريجية وقد تستغرق وقتًا طويلًا. أبقِ تبويب الموقع مفتوحًا في الهاتف حتى تنتهي، لأن هذه النسخة لا تدير مهام في الخلفية.
- تستعمل أداة تقييد المعدل في Cloudflare حدًا تقريبيًا محليًا، وهو ليس حدًا صارمًا عالميًا على بيانات اعتماد Internet Archive. إذا زاد الاستخدام العام، ينبغي إضافة حماية ضد إساءة الاستخدام وإدارة حصص الحساب قبل التوسع.
- استخدم الأداة على المقالات التي تملك حقوق حفظها أو لديك إذن مناسب لاستخدامها، مع الالتزام بشروط المواقع والخدمات.

## تنسيق ملفات Word

اسم ملف التنزيل ثابت: `الأرشيف.docx`. يحتوي المستند على عنوان «الأرشيف»، ثم عنوان كل مقال في نمط `Heading 1`، والعناوين الداخلية في نمط `Heading 2`.

- الخط Arial في جميع الأنماط.
- Title بحجم 22px، وH1 بحجم 18px، وH2 بحجم 16px، وكلها Bold.
- الفقرات والقوائم 14px، وبيانات الكاتب والموقع وتاريخ النشر والروابط 12px.
- المقالات العربية بمحاذاة يمينية واتجاه RTL، والإنجليزية بمحاذاة يسارية واتجاه LTR، بما يشمل البيانات الوصفية. تبقى حروف الروابط داخل النص العربي في مقاطع LTR لسلامة عرض عنوان URL.
- في ملف يجمع لغتين يُحدَّد اتجاه المستند وفق اللغة الغالبة في عناوين المقالات والنصوص.

تُحوّل وحدات px إلى وحدات Word بنسبة 0.75pt لكل 1px.

## التطوير والاختبار

```bash
npm ci
npm run dev
npm test
npm run deploy
```

- `src/worker.js` يحتوي واجهة API واستخراج صفحات المقالات ومهام Wayback.
- `src/utils.js` يحتوي التحقق من الروابط وترشيح المقالات.
- `public/` يحتوي الواجهة ومولّد DOCX دون اعتماديات إضافية.
- `wrangler.jsonc` إعداد Workers والملفات الثابتة وضوابط معدل الطلبات.

**حالة الاختبار:** تشمل المجموعة اختبارات منطقية، وتشغيل الواجهة في DOM محاكى، وتشغيل Worker و`HTMLRewriter` فعليًا داخل Miniflare محلي. تُحاكى ردود Siteverify ومواقع الأخبار وInternet Archive، وتُمنع أي اتصالات خارجية غير معرفة في بيانات الاختبار. تثبّت GitHub Actions الاعتماديات بواسطة `npm ci` ثم تنفذ `npm test`؛ نجاحها لا يثبت عمل الخدمات الخارجية. انظر [تقرير مراجعة Turnstile وحدود التحقق](docs/turnstile-review-2026-11-02.md).

لفحص الواجهة محليًا في متصفح دون أي أرشفة حقيقية، شغّل `node tests/preview-server.mjs --port 5173` وافتح `http://localhost:5173`. استخدم `https://news.example.org/stories/1000` للمقال و`https://news.example.org/author/reporter` لصفحة الكاتب؛ هذه عناوين تجريبية تعترضها المحاكاة. يتضمن وضع المعاينة تنبيهًا ظاهرًا، ولا تُنشر ملفات `tests/` ضمن أصول الموقع.

## التحقق الأمني عند استخراج المقالات

أصبح Turnstile مطلوبًا على مستوى Cloudflare Worker قبل استخدام `/api/inspect` أو `/api/article`، بما يشمل اكتشاف صفحة الكاتب، الصفحات التالية، واستخراج نصوص Word. عند نجاح الاختبار يصدر تصريح موقّع صالح لمدة ساعة لصفحة المصدر ولموقع الناشر نفسه، ومرتبط بالمتصفح والشبكة. يحتفظ المتصفح بالتصريح في ذاكرة الصفحة فقط، ويطلب اختبارًا آخر عند انتهائه. ويظل طلب الأرشفة في Internet Archive محميًا باختبار Turnstile مستقل. تستخدم هذه الحماية مفتاحَي `TURNSTILE_SITE_KEY` و`TURNSTILE_SECRET_KEY` المضافين مسبقًا إلى Cloudflare.

هذه الحماية تحد من الاستخدام الآلي لكنها لا تمنع كل البوتات، ويظل ضبط حدود السرعة والاستخدام ضروريًا.

## تثبيت Turnstile عبر عمليات النشر

المفتاح العام `TURNSTILE_SITE_KEY` موثّق في `wrangler.jsonc` ضمن `vars`؛ وهو مفتاح متصفح عام وليس سرًا. أُضيف `keep_vars: true` للحفاظ على المتغيرات التي تُضبط من لوحة Cloudflare عند استخدام `wrangler deploy`. يبقى المفتاح `TURNSTILE_SECRET_KEY` سرًا في بيئة Production داخل Cloudflare ولا يُحفظ في المستودع. لا تنسخ المفتاح السري إلى `wrangler.jsonc`. تعرض `/api/status` مؤشرات منطقية لفحص وجود المفتاحين دون كشف السر.

## إصلاح موضع Turnstile

تم فصل الواجهتين: موضع `#inspect-turnstile-widget` داخل نموذج استخراج المقالات، وموضع `#archive-turnstile-widget` داخل نتائج الأرشفة. يُنشأ اختبار كل عملية عند الضغط عليها فقط، باستدعاء Turnstile عبر محدّد CSS يبدأ بـ`#` كما في توثيق Cloudflare، ولا يُنشأ داخل قسم مخفي. لكل عملية `action` مستقل (`inspect` و`archive`) ويظل التحقق على الخادم إلزاميًا.

## تجديد التحقق وإعادة المحاولة

لكل محاولة تحقق واجهة جديدة وردود مرتبطة بالمحاولة نفسها، حتى لا يُستخدم رد متأخر من محاولة سابقة. تنتهي مهلة انتظار الواجهة بعد دقيقتين، وتُعالج أخطاء التحقق وانتهاء التحدي وعدم دعم المتصفح مع إعادة إتاحة الأزرار. ينتهي انتظار Siteverify على الخادم بعد 15 ثانية، دون إصدار تصريح عند الفشل.

يحتفظ المتصفح بتصاريح الاستخراج والأرشفة في ذاكرة الصفحة فقط، ويجددها قبل انتهاء الصلاحية. إذا رفض الخادم تصريحًا بسبب انتهائه أو تغيّر الشبكة، يصدر رمز خطأ محدد يسمح بتجديد التحقق وإعادة الطلب مرة واحدة. تشترك طلبات Word المتزامنة ومتابعات الأرشفة في محاولة التجديد نفسها. يظل تصريح الاستخراج مرتبطًا بالمصدر والناشر، وتصريح الأرشفة بالروابط المحددة، ويظل كلاهما مرتبطًا بالنطاق والمتصفح والشبكة.

لا يُعاد إرسال طلب حفظ إلى Internet Archive تلقائيًا بعد خطأ شبكة أو استجابة غير مؤكدة. يُسجل حينها ضمن الحالات غير المؤكدة. تجديد التصريح أثناء متابعة الحفظ يستعلم عن المهمة المقبولة نفسها، ولا ينشئ مهمة أرشفة أخرى. وتعني مؤشرات `/api/status` أن المفاتيح موجودة في إعدادات الخادم فقط، ولا تؤكد صحتها أو نجاح الاتصال بالخدمة.
